# 提案 + 导演单（第 1 步写，存成项目根目录的 `DIRECTOR.md`）

分两部分：**提案**是给用户看、等用户拍板的两张表；**导演单**（A–F）是你自己做片时对着核对的细节。先写提案，贴给用户，确认后再补导演单、再动手。

## 提案（第 1 步写完就停，等用户确认）

### 表 1：风格大纲

| 项 | 方案 | 为什么这么选 |
|---|---|---|
| 主题风格 | 一个有名字的风格 + 一句话描述（有什么、没有什么） | 从主题和用户原话推出来，不自由发挥 |
| 色板 / 字体 / 质感 | 3–5 个颜色、字体、材质 | |
| 母题 / 高光 | 贯穿全片的视觉意象；只属于这条片子的那一下（第几秒） | |
| 配音 | 来源（自己的声音 / HeyGen 公共声音 / Gemini）、语气、稿子全文 | |
| 配乐 | 曲风一句话（「有推进力的摇滚，鼓点干脆」）+ 2–3 首候选（曲库 id、时长、BPM、哪段对哪段），附试听文件 | 贴主题、贴情绪；产品介绍、宣传片默认要动感、有推进力 |
| 音效 | 转场用什么、关键帧用什么，都从曲库找 | 每个切点、每个关键动作都要有 |
| 节奏 / 时长 / 规格 | 节奏档、总时长、横竖版 | |
| 和最近作品的区别 | 对照作品记录，6 项里哪几项不同 | |

### 表 2：分镜

| 镜头 | 时间 | 配音 / 字幕 | 画面里渲染什么 | 以什么形式出现（动作、景别、相机） | 转场 | 音效 | 配乐 |
|---|---|---|---|---|---|---|---|
| s1 | 0–4.1s | 「做视频最难的…」 | 灯箱上走片的胶片，声带和画格错开 | 齿孔大特写 → 拉开；2.35s 急停；红蜡笔写「差 3 帧」 | 硬切（卡拍） | 0s 走片声；2.35s 急停咔哒 | 前奏，压在人声下 |

时间在第 1 步只是估计（按稿子字数，每秒 4.3 字）；确认后配完音，用 `film_data.py` 的建议切点换成准确时间。

### 风格预览 HTML（第 1.5 步）

两张表写完后，立即生成风格预览页面：

1. 从 `templates/style-preview.html` 复制到项目的 `style-preview/` 目录，按方案数量命名（`style-A.html`、`style-B.html`……）。
2. 改 `:root` 里的 CSS 变量：色板 `--c1` ~ `--c5`、字体 `--font-title` / `--font-body` / `--font-accent`、质感 `--grain-opacity` / `--vignette-opacity`。
3. 填内容：`#style-name` 和 `#style-desc` 写方案名和一句话定义；`#palette` 的色块按风格给色值和用途；`#type` 换成方案的标题、手写、正文示例文字；`#texture` 的质感层增减标签（纸纹、毛玻璃、扫描线……）；`#comp` 的 canvas 按分镜第一个镜头画构图示意（色块占位即可，不必精细）；`#checklist` 写该方案的元素清单和禁止项。
4. 只有一个方案时也出一份预览——用户看到实际效果才好判断。

**贴给用户时**：两张表直接贴在对话里，配乐试听文件和风格预览页面一起发。告诉用户「在浏览器里打开 `style-preview/` 下的 HTML 文件看实际效果」。结尾问一句「哪个方向更好？哪里要改？确认后我开始配音和渲染」。用户改了就改表和预览再贴，直到明确说可以。

## A. 硬要求（逐字抄用户原话，交付前逐条打勾）

| # | 用户原话 | 做到的样子（能判对错） | 核对 |
|---|---|---|---|
| 1 | 例：「配乐用我给的 song.mp3，副歌对上 logo」 | 用这个文件；副歌第一拍 = logo 砸下那一帧 | ☐ |
| 2 | 例：「不要旁白」 | 音轨里没有人声，台词全是画面上的字 | ☐ |

点名的歌、工具、风格、**给出的参考图**、时长、横竖版、有无旁白配乐、点名的画面类型（「复原场景」「地势图」「群战」），**全部**进这张表。用户说「多」「要足」，按举例的 2–3 倍去做，举例不是上限。

## B. 关键因素（每项一两句）

1. **风格**：一个有名字的风格（见 `style-cards.md`，若提供了参考图则从图中逆向提炼），加元素清单：
   - 色板 3–5 色，写十六进制与用途（底色、主体、点缀）
   - 线条、材质和纹理（颗粒/纸纹/光感/毛玻璃）、光、字体气质
   - **不许出现的**（例：不要渐变底、不要霓虹、不要居中小字开场）
2. **内容核心**：故事写出反转；讲解写出几个要点，以及每个要点要让观众**感到**的那件事；宣传片写出最重要的 3 个卖点。
3. **声音**：有没有配音、配乐从哪来、卡不卡点、哪一刻对哪一拍。细节交给 video-audio。
4. **规格**：横竖版、分辨率、帧率、时长。
5. **节奏档**（见 `motion.md` 第 1 节）：讲述 / 快剪 / MV，可以按段分。写起止秒、哪一档、为什么。例：「0–12s 快剪（产品日常），12s 起 MV（高潮连砸三个卖点）」。
6. **景别计划**：全片至少 4 种景别、2 种角度；写出开头、高潮、落版各用什么景别。
7. **个性化表达**（见 `originality.md`）：
   - 母题：一个从内容里长出来的视觉意象，转场和高潮都从它变出来。
   - 高光：一处换个主题就做不出来的设计，写清第几秒、发生什么。
   - 对照作品记录：最近 3 条的风格、主色板、主字体、开场、配乐曲风、收尾，至少 4 项不同；撞了的写清换成了什么。
   - 用了「AI 默认审美清单」里的哪几样、为什么。

## C. 导演层（让片子「高级」的部分）

1. **观众先看哪**：每段的主体、次主体、背景各做什么。
2. **层次**：前景偶尔掠过、中景主事件、远景气氛。
3. **节奏曲线**：前 2 秒钩子 → 发展 → 高潮（落在音乐高潮或故事反转）→ 收束（落版停够 1.5s）。
4. **高潮那一刻**：在第几秒、对哪一拍、用什么景别、什么冲击。最重的一刻前面留一拍安静。
5. **相机路线**：每段推、摇、跟什么，推完停在哪；镜头之间用哪几种转场轮换。

## D. 禁止项（默认全部生效，再加本片特有的）

- 不加「代码生成」「AI 制作」角标、代码浮窗、技术参数、水印。
- 不用渐变底配居中大字开场；不全片淡入淡出；不用闪白遮转场。
- 不加标签页、页码、页眉、「01/07」步骤号、面包屑。
- 字不出画、不被挡；同一时刻屏幕上的大字不超过一句。
- 不编数字、人名、日期；不画假的产品界面（用真截图）。
- 不用没授权的音乐、图片、人物照片。
- 本片特有：……

## E. 分镜（每个镜头一行）

| 镜头 | 起–止（秒） | 对应 | 景别 / 角度 | 主任务（观众此刻看什么） | 主动作（这个镜头自己的事） | 相机 | 转场 / 音效（不能空） |
|---|---|---|---|---|---|---|---|
| s3 | 8.0–11.2 | 第 5–8 拍 / 配音第 3 句 | 中景 / 低角度 | 产品第一次亮相 | 机身从右侧 `beat()` 冲入，落定后三个卖点 `after()` 依次弹出 | 先不动；落定那拍顿推，推完停住 | 甩镜头进；落定那帧「咚」 |

- 一个镜头 1.5–5 秒，越到高潮越短；讲解片按配音的句子切。起止从 `timeline.json` 抄。
- 相邻两行景别不同；全表至少 4 种景别。
- 「主动作」一栏写**这个镜头自己的事**。整列复制同一句，做出来就是每个镜头同一套循环。
- 高潮段另写事件表：每件事落在第几小节第几拍、是什么、是不是重击；每 2.4 秒至少 5 件不同的事。

## F. 验收标准（机器或一眼就能核对）

- 时长 X 秒 ±10%，分辨率 W×H，帧率 F。
- A 表全部打勾。
- `video_qa.py` 全过：无黑帧、无死画面、画面不空、版式不雷同、每秒有变化。
- `audio_qa.py` 全过：响度、真峰值、音画等长；卡点片切点落拍 ≥ 70%。
- 评分表 10 项都 ≥ 8 分。
