# 自检、返工、翻车清单

**做完不看，等于没做完。** Agent 能看图：出拼图，像挑剔的导演一样看，再用数据确认。

## 1. 静帧自查（全片渲染前）

1. 挑 4–8 个关键时刻：开头 0.5s、每段代表画面、高潮那一帧、落版。
2. `node <video-director>/scripts/render.mjs index.html --out out --stills 0.5,3,8,15,22,28`，看 `out/stills/sheet.jpg`。其他工具用 ffmpeg 抽帧拼图。
3. 逐张对照导演单：风格元素每张都有吗？主体够大吗？字读得清吗？景别有没有轮换？
4. 按评分表打分，<8 分的先修。静帧上修一个问题几分钟，全片渲完再发现要多花十几分钟。

## 2. 成片自检

```bash
python3 <video-director>/scripts/video_qa.py final.mp4 --expect-size 1080x1920 --expect-dur 30 --out qa
python3 <video-audio>/scripts/audio_qa.py final.mp4 --cuts $(cat qa/cuts.txt) --beats-src bgm_in_film.wav
```

查落拍的两个坑（都实测踩过）：
- **拍点用 `--beats-json timeline.json`**，也就是画面排切点用的那一份。重新测一遍可能测错：截出来的一段曲子常被测成半速，拍点少一半。实在要测，`--beats-src` 传片子里实际播放的那一段配乐，不传整首原曲。
- **切点用真正的镜头切点**（页面里的 `SHOT`，或 `film_data.py` 的 `CUTS`）。`cuts.txt` 是画面突变检测出来的，会把镜头内的事件（换图、开灯、投影换帧）也算进去，这些事件跟着音效走，不该按拍点判。
- 有意不落拍的切点（比如对准曲子的能量跳升、对准开口），在交付说明里写清楚。

| 检查 | 阈值 | 报警时怎么改 |
|---|---|---|
| 尺寸、时长 | 尺寸一致，时长 ±10% | 改渲染参数 |
| 黑帧 | 片中没有 0.3s 以上的黑帧（片头片尾淡入淡出不算） | 段落之间别淡到黑，换成第 4 种转场 |
| 死画面 | 没有超过 1.5s 的冻帧（最后 2s 落版不算） | 加相机运动、加镜头，每 2–4 秒要有新东西 |
| 画面空不空 | 一半以上面积是同一种底色的帧 < 50% | 放大主体、铺满场景，别在空底上摆卡片 |
| 版式雷同 | 相隔 3 秒以上的画面平均相似度 ≤ 0.45 | 换景别、换角度、换构图 |
| 每秒变化 | 相邻两秒平均相似度 ≤ 0.82 | 像幻灯片翻页：加相机运动、加切换 |
| 切点 | 只报数量和最长镜头 | 结合片型判断；卡点片交给 `audio_qa.py` 查落拍 |

阈值来自上游用原片（动画、实拍、地图类）和翻车片的校准。只有两种情况可以关掉检查：纯色大底快切的动态排版加 `--allow-solid-bg`；固定界面的网页录屏、分步说明书加 `--fixed-layout`。其他风格不许靠开关消警告。

数据过了还要用眼睛看：

- `qa/联系表.jpg`（每 2 秒一格）：相邻两格景别不同吗？至少看到 4 种景别吗？有没有哪段丢了质感层？关掉声音，能看出片子讲了什么吗？
- `qa/手机尺寸.jpg`（每秒一格，360 宽）：字还读得清吗？
- 快动作附近抽 12 帧连着看：`ffmpeg -ss <t−0.2> -i final.mp4 -vf "scale=320:-1,tile=12x1" -frames:v 1 qa/strip.jpg`。数一数同一时间有几样东西在从 A 到 B；看动作是不是快起慢停、有没有一直在原地晃。

## 3. 打分和返工

按 SKILL.md 的 10 项打分，写进 `qa/评分.md`：

```
硬要求 9｜视觉与风格 7｜开头 8｜可读性 6｜运动 8｜节奏 8｜声画 9｜内容 8｜构图 8｜技术 9
最差 3 个问题：
1. 12.4–14.0s 两句字幕叠在一起（可读性）
2. 第 3 段纸纹太淡，缩小后认不出撕纸风（视觉与风格）
3. 20s 主角颜色和前面不一致（视觉与风格）
修法：……
```

- **视觉高级感是一票否决项（最重要）**：视觉效果必须高级、有真实材质质感与设计感。如果画面看起来**很平庸、塑料感、缺乏高级感、或者有一眼 AI 味**（深色底悬浮小卡片、居中小字全体淡入、粗糙大纯色块、廉价发光描边、黑黄俗气大字等模板套路），第 2 项直接不及格（< 8 分），**必须一票否决、立刻打回重做，绝不交付**。
- 修完只重渲受影响的秒数，重新合成，再跑一遍自检和打分。**最多 3 轮**。第 3 轮还没到 8 分，把差在哪写进交付说明，别假装没问题。
- **改一项、看全部，防跷跷板**：每轮把所有检查和上一轮逐项比。哪一项比上一轮差一成以上，先查是不是这次改动挤掉了别的层，挤掉了就补回去。

## 4. 翻车清单（动手前过一遍，交付前再过一遍）

| # | 默认会怎么做 | 应该怎么做 |
|---|---|---|
| 1 | 风格没落实，退回「深色底 + 居中小字 + 全体淡入」 | 风格翻译成元素清单，每帧都要有 |
| 2 | 做成网页 / 幻灯片：每个镜头同一个版式，带标签徽章、页码，主体小、留白大 | 每个镜头一个铺满的场景，构图轮换，去掉界面装饰 |
| 3 | 讲解片做成仪表盘：左边大数字，右边小小的静态图 | 每个要点让物体做一个动作，把道理演出来 |
| 4 | 「砸几句大字」做成角落里的小字淡入 | 字宽 ≥ 画面 1/3，放大回弹砸进来，配重拍 |
| 5 | 为了卡点越切越快，字读不完 | 可读性优先；停留 ≥ 字数 × 0.25s + 0.5s |
| 6 | 要求卡点，20 秒只切 2 刀，靠叠化过渡 | 高能段每 1–2 拍硬切一刀并配冲击 |
| 7 | 机位不动，转场只有淡入淡出或闪白 | 每段至少一种相机运动；4–5 种转场轮换 |
| 8 | 同一张底图反复出现，机位和焦点不变 | 再出现时换景别、换焦点、换光 |
| 9 | 动起来又慢又软：一个动作 1 秒多、两头慢进慢出、镜头从头推到尾、满屏原地晃 | 按节奏档定时长；快起慢停；推完要停；原地晃只当底噪 |
| 10 | 改快了，但每个动作一个样：同一个时长、同一条缓动 | 按动作类型挑写法：砸下、入场、弹出、走位拉开时长 |
| 11 | 热闹靠循环凑：同一道刀光每拍重播 | 按事件写，每件事只发生一次，冲击逐级加码 |
| 12 | 高潮一闪而过，没有特写 | 大特写 + 慢放或定格 + 最重的一拍，前面留一拍安静 |
| 13 | 用户点名的歌、工具、画面类型被悄悄换掉 | 照用；拿不到就在交付说明里写原因和替代品 |
| 14 | 把举例当上限：说「几种」就只做三种 | 用户说「多」「要足」，按 2–3 倍做 |
| 15 | 画面上加「代码生成」「AI 制作」角标 | 不加任何自证元素 |
| 16 | 编数字、论文、日期 | 查证；查不到就标「示意」或不写 |
| 17 | 一口气写完所有代码才第一次渲染，发现跑不起来 | 第一步就渲出第一帧 |
| 18 | 没出样张就全片渲染，最后整体返工 | 静帧自查不能省 |
| 19 | 没点名框架，却默认走了 HyperFrames / Remotion | 用户没点名就自己写 seek(t) 代码 |
| 20 | 趋于雷同：每条片子都是黑黄巨字、每拍白闪震屏、EDM 加品牌叮、「一句话」「一条龙」套话 | 先读作品记录拉开；母题从内容里找；重冲击最多 2 次；文案用项目里的真东西 |
| 21 | 没确认方向就开做：风格、配乐自己挑，做完用户说不对，整条重来 | 先贴提案两张表，等用户确认 |
| 22 | 配乐和人声一样响（实测旧版只低 1.2 dB） | 用 `mix.py`，说话时配乐至少低 12 dB，它会量 |
| 23 | 转场、关键帧没有音效，画面切了声音没反应 | 每个切点一个转场音效，每个关键动作一个命中音效 |
| 24 | 配乐自由发挥（给产品介绍配慵懒爵士） | 曲风从主题和情绪推；产品介绍、宣传片默认要动感、有推进力 |

## 5. 交付说明（`交付说明.md`）

1. 一句话：这条片子是什么、多长、什么规格。
2. 硬要求逐条：做到 / 部分 / 没做到（没做到写原因）。
3. 做法：工具和路线。
4. 素材和声音来源：每个外部素材的来源和授权。
5. 自检：跑了几轮、每轮剩几个问题、最后一次评分、还差什么。
